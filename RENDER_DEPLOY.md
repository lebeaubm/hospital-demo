# Quick Start: Deploy to Render

This guide will help you deploy the Hospital Demo to Render in just a few steps.

## Prerequisites

1. **GitHub Repository**: Push your code to GitHub
2. **Render Account**: Sign up at https://render.com (free tier available)
3. **Stripe Account** (optional): For payment features

## Step 1: Push to GitHub

If you haven't already:

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git push -u origin main
```

## Step 2: Deploy to Render

### Option A: Using the Blueprint (Recommended - Deploys Everything at Once)

1. Go to https://render.com/dashboard
2. Click **"New"** → **"Blueprint"**
3. Connect your GitHub repository
4. Render will automatically detect `render.yaml` and create:
   - PostgreSQL database
   - Backend API service
   - Frontend static site

5. **Set required environment variables** in the Render dashboard:
   - **Backend Service**:
     - `ALLOWED_HOSTS`: Copy your backend URL from Render (e.g., `hospital-demo-api.onrender.com`)
     - `CORS_ALLOWED_ORIGINS`: Will set after frontend deploys
     - `STRIPE_SECRET_KEY`: Your Stripe secret key (optional)
     - `STRIPE_PUBLISHABLE_KEY`: Your Stripe publishable key (optional)
   
   - **Frontend Service**:
     - `VITE_API_URL`: Your backend URL (e.g., `https://hospital-demo-api.onrender.com`)

6. **Update CORS** after frontend deploys:
   - Go to backend service settings
   - Update `CORS_ALLOWED_ORIGINS` with your frontend URL (e.g., `https://hospital-demo-frontend.onrender.com`)
   - Save and redeploy backend

### Option B: Manual Setup (Step by Step)

#### 2.1 Create PostgreSQL Database

1. Dashboard → **"New"** → **"PostgreSQL"**
2. Name: `hospital-demo-db`
3. Database: `hospital_demo`
4. User: `hospital_demo_user`
5. Click **"Create Database"**
6. Copy the **Internal Database URL** (starts with `postgresql://`)

#### 2.2 Deploy Backend API

1. Dashboard → **"New"** → **"Web Service"**
2. Connect your GitHub repository
3. Configure:
   - **Name**: `hospital-demo-api`
   - **Root Directory**: `backend`
   - **Runtime**: `Python 3`
   - **Build Command**: `./build.sh`
   - **Start Command**: `gunicorn backend.wsgi:application`
4. **Environment Variables**:
   ```
   SECRET_KEY=<auto-generated by Render or use: python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())">
   DEBUG=False
   ALLOWED_HOSTS=<your-backend-url>.onrender.com
   CORS_ALLOWED_ORIGINS=https://<your-frontend-url>.onrender.com
   DATABASE_URL=<paste-internal-database-url>
   STRIPE_SECRET_KEY=<your-stripe-key> (optional)
   STRIPE_PUBLISHABLE_KEY=<your-stripe-key> (optional)
   ```
5. Click **"Create Web Service"**

#### 2.3 Deploy Frontend

1. Dashboard → **"New"** → **"Static Site"**
2. Connect your GitHub repository
3. Configure:
   - **Name**: `hospital-demo-frontend`
   - **Root Directory**: `frontend`
   - **Build Command**: `npm install && npm run build`
   - **Publish Directory**: `dist`
4. **Environment Variables**:
   ```
   VITE_API_URL=https://<your-backend-url>.onrender.com
   ```
5. Under **"Redirects/Rewrites"**:
   - Source: `/*`
   - Destination: `/index.html`
   - Action: `Rewrite`
6. Click **"Create Static Site"**

## Step 3: Post-Deployment Setup

### 3.1 Create Superuser (Admin Account)

1. Go to your backend service in Render dashboard
2. Click **"Shell"** tab
3. Run:
   ```bash
   python manage.py createsuperuser
   ```
4. Follow prompts to create admin account

### 3.2 Seed Demo Data (Optional)

In the Render shell:

```bash
# Seed doctors
python manage.py migrate core 0002_seed_doctors

# Seed patients and appointments  
python manage.py migrate core 0004_seed_patients_and_appointments
```

Or create test accounts manually in the shell:

```bash
python manage.py shell
```

Then:

```python
from core.models import User
User.objects.create_user(email='patient@example.com', password='Pass1234!', role='PATIENT', first_name='Demo', last_name='Patient')
User.objects.create_user(email='staff@example.com', password='StaffPass123!', role='STAFF', is_staff=True, first_name='Demo', last_name='Staff')
```

## Step 4: Verify Deployment

1. **Backend API**: Visit `https://your-backend-url.onrender.com/api/doctors/`
2. **Frontend**: Visit `https://your-frontend-url.onrender.com`
3. **Test Login**: Try logging in with your demo accounts
4. **Admin Panel**: Visit `https://your-backend-url.onrender.com/admin/`

## Step 5: Configure Stripe (Optional)

If you want payment features:

1. Get your Stripe keys from https://dashboard.stripe.com/test/apikeys
2. Add to backend environment variables:
   - `STRIPE_SECRET_KEY`: Your secret key
   - `STRIPE_PUBLISHABLE_KEY`: Your publishable key
3. The frontend will automatically detect Stripe availability

## Common Issues

### Issue: Build fails with "Permission denied" for build.sh

**Solution**: The build.sh file needs to be executable. Run locally:
```bash
git update-index --chmod=+x backend/build.sh
git commit -m "Make build.sh executable"
git push
```

### Issue: CORS errors in browser console

**Solution**: Update backend `CORS_ALLOWED_ORIGINS`:
- Must include `https://` protocol
- No trailing slash
- Match exactly your frontend URL

### Issue: Frontend shows "Network Error"

**Solution**: Check `VITE_API_URL` in frontend environment variables:
- Must include `https://` protocol
- No trailing slash
- Must rebuild after changing environment variables

### Issue: Database connection errors

**Solution**: 
- Verify `DATABASE_URL` is set in backend environment variables
- Use the **Internal Database URL** (not External)
- Check database is running in Render dashboard

### Issue: Static files (CSS) not loading

**Solution**: The build script automatically runs `collectstatic`. If issues persist:
- Check logs for collectstatic errors
- Verify WhiteNoise is in MIDDLEWARE (already configured)
