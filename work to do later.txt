WORK TO DO LATER: Configure Real Email Sending
==============================================

Currently, the app uses Django's console email backend (prints emails to terminal).
To send real emails in production, follow these steps:

STEP 1: Choose an Email Provider
---------------------------------
Pick one of these options:

A) Gmail (easiest for testing)
   - Free for low volume
   - Requires "App Password" (not your regular password)
   
B) SendGrid
   - Free tier: 100 emails/day
   - Easy API setup
   - Website: https://sendgrid.com/
   
C) AWS SES (Amazon Simple Email Service)
   - Very cheap (~$0.10 per 1,000 emails)
   - Requires AWS account
   
D) Mailgun
   - Free tier: 5,000 emails/month
   - Good documentation

E) Other: Postmark, Mailjet, etc.


STEP 2: Get SMTP Credentials
-----------------------------

FOR GMAIL:
1. Go to your Google Account settings
2. Enable 2-Factor Authentication
3. Go to Security → 2-Step Verification → App Passwords
4. Generate an app password for "Mail"
5. Save the 16-character password

FOR SENDGRID:
1. Sign up at sendgrid.com
2. Go to Settings → API Keys
3. Create API Key with "Mail Send" permissions
4. Save the API key (starts with "SG.")

FOR AWS SES:
1. Sign up for AWS
2. Go to SES console
3. Verify your sender email address
4. Get SMTP credentials from "SMTP Settings"


STEP 3: Update Backend Environment Variables
---------------------------------------------

Edit backend/.env file (create it if it doesn't exist):

```
# Email Configuration for Production
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend

# For Gmail:
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-app-password-here

# For SendGrid:
# EMAIL_HOST=smtp.sendgrid.net
# EMAIL_PORT=587
# EMAIL_USE_TLS=True
# EMAIL_HOST_USER=apikey
# EMAIL_HOST_PASSWORD=your-sendgrid-api-key-here

# For AWS SES:
# EMAIL_HOST=email-smtp.us-east-1.amazonaws.com
# EMAIL_PORT=587
# EMAIL_USE_TLS=True
# EMAIL_HOST_USER=your-aws-smtp-username
# EMAIL_HOST_PASSWORD=your-aws-smtp-password

# From address (what recipients see)
DEFAULT_FROM_EMAIL=noreply@yourhospital.com

# Staff inbox (where appointment requests are sent)
STAFF_INBOX_EMAIL=staff@yourhospital.com
```

IMPORTANT: Never commit .env file to Git!
Add this line to .gitignore if not already there:
```
.env
```


STEP 4: Verify Email Domain (Optional but Recommended)
-------------------------------------------------------

To avoid emails going to spam:

1. Add SPF record to your domain's DNS:
   TXT record: v=spf1 include:_spf.google.com ~all
   (or appropriate include for your provider)

2. Add DKIM record (provided by your email service)

3. Add DMARC record:
   TXT record for _dmarc: v=DMARC1; p=none; rua=mailto:postmaster@yourdomain.com

STEP 7: Handle Email Failures
------------------------------

Add retry logic (future enhancement):

In backend/core/notifications.py:

```python
# Add retry decorator
from django.core.mail import send_mail
import time

def send_email_with_retry(email, max_retries=3):
    for attempt in range(max_retries):
        try:
            email.send(fail_silently=False)
            return True
        except Exception as e:
            if attempt == max_retries - 1:
                raise e
            time.sleep(2 ** attempt)  # Exponential backoff
    return False
```


STEP 8: Production Deployment Notes
------------------------------------

When deploying to production (Render, Heroku, AWS, etc.):

1. Set environment variables in hosting platform dashboard
   (Don't use .env file in production)

2. For Render.com:
   - Go to your web service
   - Environment tab
   - Add all EMAIL_* variables
   - Click "Save Changes"

3. For Heroku:
   heroku config:set EMAIL_HOST=smtp.gmail.com
   heroku config:set EMAIL_PORT=587
   (etc. for each variable)

4. Restart your application after setting variables


TROUBLESHOOTING
---------------

Issue: Emails go to spam
Solution: 
  - Verify domain with SPF/DKIM
  - Use professional "from" address
  - Avoid spam trigger words
  - Test with mail-tester.com

Issue: Gmail blocks login
Solution:
  - Use App Password (not regular password)
  - Enable "Less secure app access" (not recommended)
  - Use SendGrid instead

Issue: Status shows "FAILED"
Solution:
  - Check error message in NotificationLog
  - Verify SMTP credentials
  - Check firewall/port 587 access
  - Try port 465 with EMAIL_USE_SSL=True

Issue: Emails not arriving
Solution:
  - Check spam folder
  - Verify recipient email is valid
  - Check email provider's logs
  - Test with different recipient

-------------------------

Low volume (<1,000 emails/month):
  - Gmail: Free
  - SendGrid: Free

Medium volume (~10,000 emails/month):
  - Gmail: Not recommended (daily limits)
  - SendGrid: ~$15/month
  - AWS SES: ~$1/month
  - Mailgun: Free tier or ~$35/month

High volume (>50,000 emails/month):
  - SendGrid: ~$90/month
  - AWS SES: ~$5/month
  - Mailgun: ~$80/month


SECURITY BEST PRACTICES
------------------------

1. Never hardcode credentials in code
2. Use environment variables
3. Rotate passwords/API keys every 90 days
4. Monitor for unauthorized usage
5. Set up rate limiting
6. Use HTTPS for production
7. Enable 2FA on email provider account

What you’d change to send real emails later
1) Choose an email delivery method

Recommended (production): transactional email provider (SendGrid, Mailgun, Postmark, Amazon SES) via SMTP or API.
Okay for testing: Gmail SMTP (more brittle, often rate-limited).

2) Switch Django’s email backend from “console” to SMTP

In settings.py, change from:

EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend"


to:

EMAIL_BACKEND = "django.core.mail.backends.smtp.EmailBackend"
EMAIL_HOST = os.getenv("EMAIL_HOST")
EMAIL_PORT = int(os.getenv("EMAIL_PORT", "587"))
EMAIL_HOST_USER = os.getenv("EMAIL_HOST_USER")
EMAIL_HOST_PASSWORD = os.getenv("EMAIL_HOST_PASSWORD")
EMAIL_USE_TLS = os.getenv("EMAIL_USE_TLS", "true").lower() == "true"
DEFAULT_FROM_EMAIL = os.getenv("DEFAULT_FROM_EMAIL", "clinic@example.com")

3) Add the env vars (don’t commit them)

Create .env (or set them in Render/hosting dashboard):

EMAIL_HOST (e.g., smtp provider host)

EMAIL_PORT (usually 587 TLS)

EMAIL_HOST_USER

EMAIL_HOST_PASSWORD

EMAIL_USE_TLS=true

(optional) STAFF_INBOX_EMAIL=frontdesk@yourdomain.com

And ensure .env is in .gitignore.

4) Provider setup you’ll need (or emails may go to spam)

Verify your sender identity (provider will require this)

Ideally use a domain you control and configure DNS:

SPF

DKIM

(optional but good) DMARC

5) Decide what “From” should be for staff-sent emails

In real systems, you usually don’t send “from each staff member’s email” unless those are verified senders. Instead:

From: clinic@yourdomain.com

Reply-To: staff member’s email

That makes deliverability easier while still letting patients reply to the staff member.

6) (Later) Move sending to the background

For a demo, sending during the request is fine. In production, better:

queue emails (Celery/RQ) so a slow SMTP server doesn’t slow your API

retry on failure

keep using your NotificationLog as the audit trail
